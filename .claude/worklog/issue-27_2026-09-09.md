## 設計上の判断

### 値オブジェクトを採用(配列にしない)
`ProgressionContext` / `ProgressionTarget` を `final readonly class` にした。
strategy 間のやり取りは今回新設する境界であり、`ProgressionService` の
「配列のみ」という既存契約とは別物なので、ここに型を付けても既存境界を汚さない。
フロントへは `toArray()` で配列化するため JSON シリアライズにも影響しない。

### 5×5 の必要セット数は定数固定
現行スキーマに種目単位の「目標セット数」列が無い
(`routine_exercises.target_sets` はルーティン×種目単位で、
メニューなしワークアウトでは存在せず `ProgressionContext` から参照できない)。
戦略名自体が「5×5」なので可変にする実用上の動機が薄いと判断し `REQUIRED_SETS = 5` で固定。
将来 種目単位の列を足す場合は `ProgressionContext` にフィールドを追加するだけで拡張できる。

## レビューで修正した点(重要)

`AdminExerciseController::update()` が、`progression_strategy` 未指定時に
**`Double` へフォールバック**する実装だった。

```php
// ✗ リニアや5x5を選んでいた種目が黙ってダブルプログレッションに戻る
'progression_strategy' => $data['progression_strategy'] ?? ProgressionStrategyType::Double->value,

// ✓ 現在の設定を維持する
'progression_strategy' => $data['progression_strategy'] ?? $exercise->progression_strategy->value,
```

エージェント自身が「API的には未指定=暗黙リセットになる」と懸念として報告していた。
UIフォームは常に現在値を送るため実害は出ていなかったが、
**設定が黙って消える種類のバグ**なので修正した。
