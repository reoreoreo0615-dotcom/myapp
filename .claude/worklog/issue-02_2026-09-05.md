## 実装内容

Laravel Breeze(vue スタック)を導入し、認証と Inertia + Vue 3 の基盤を整えた。
**これにより http://localhost/ が Laravel の初期ページからアプリのログイン画面に変わった。**

## 導入方針とその根拠

Laravel 12 以降、認証スターターキットは `laravel new` 時に選択する方式に変わっており、
既存プロジェクトへの後付け手順は自明ではない。調査の結果:

- `laravel/breeze` v2.4.2 が Laravel `^11|^12|^13` を正式サポートしていることを確認 → **採用**
- `laravel-lang/common`(日本語化パッケージ)は Laravel 13 非対応
  (`illuminate/console` の要求が `^12` まで)→ **不採用**。`lang/ja/` を手動作成

## 設計上の判断

### 1. Breeze が上書きした Tailwind v3 構成を v4 に復元した

Breeze の vue スタックは **Tailwind v3 用のスキャフォールド**を生成する。
本プロジェクトは Tailwind v4(`@tailwindcss/vite`)を使っているため、放置すると
CSS が壊れるか v3/v4 混在で原因不明のスタイル崩れが起きる。

- `resources/css/app.css` を v4 構文(`@import 'tailwindcss'`)に戻す
- `vite.config.js` に `@tailwindcss/vite` を再追加
- v3用の `tailwind.config.js` / `postcss.config.js` を削除
- `package.json` の `tailwindcss` を `^4.0.0`、`@tailwindcss/forms` を `^0.5.11` に修正

**`.claude/CLAUDE.md` に「Tailwind v4」と明記してあったことがこの事故を防いだ。**

### 2. ルート `/` はログイン画面を 200 で直接返す

リダイレクトではなく `AuthenticatedSessionController::create()` を直接返す。
認証済みなら `/dashboard` へリダイレクト。

### 3. APP_NAME を Laravel → Overload に変更

ブラウザタブに `Overload` と表示される。

## 検証結果(自分で実行)

```
/                        → 200、Inertiaコンポーネント Auth/Login を配信
/dashboard(未認証)      → 302 → /login
/profile(未認証)        → 302 → /login
登録POST                 → 302 → /dashboard、users にレコード作成
/dashboard(認証済み)    → 200、Dashboard + auth.user を配信
ログアウト後の /dashboard → 302 → /login
テスト                   → 58件全パス(既存35 + Breeze生成23)
```

既存実装の保護も確認: `User` の3リレーション、`phpunit.xml` の MySQL 設定、種目マスタ31件。

## 残課題

- **`verified` ミドルウェア**が dashboard に付いているが `User` が `MustVerifyEmail` 未実装のため実質無効
- **`laravel/sanctum`** が Breeze の依存で入ったが未使用(害はないため残置)
- ダッシュボードの中身は Breeze の初期状態。**Issue #4 で本実装する**
