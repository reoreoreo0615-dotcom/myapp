## 設計上の判断

### 経過時間は開始時刻からの差分で計算する
`setInterval` のカウントを足し込まない。`startedAt`(epoch ms)を保持し、
0.5秒ごとに `Date.now()` を取り直して**差分**で毎回再計算する。

ブラウザはバックグラウンドタブの `setInterval` を間引くため、
足し込み方式だとジムで別アプリを開いて戻ったときに時間が狂う。

さらに `localStorage`(`overload:rest-timer:<workoutId>`)に
`{targetSeconds, startedAt, running}` を永続化し、再マウント時に復元する。

### 目標到達通知は「表示中に跨いだ瞬間」のみ
離れていた間に既に超過していた場合は、復元時に `notified` を先に立てて抑制する。
戻った瞬間に驚かせて鳴らないようにするため。

### タイマーはワークアウト単位で1つ
種目ごとの並行タイマーは作らない。別種目のセットを記録すると、
その種目の既定休憩時間で上書きする。常に「直近のセットの休憩」を計るのが目的のため。

### 自動開始はサーバーが記録を確認した瞬間(`onSuccess`)
クリック直後の楽観的開始ではなく、記録に失敗したときに誤ってタイマーが
始まらないことを優先した。

### タイマーは使うまで画面に出ない
`targetSeconds === null` の間はバー自体が存在しない。
記録前は画面に一切余計な要素が出ず、操作を邪魔しない。

## iOS Safari の制約(調査結果)

| 項目 | 結果 |
| --- | --- |
| 音の自動再生制限 | ページ内で最初に指が触れた瞬間(`pointerdown`, `{once:true}`)に `AudioContext` を生成・`resume()` してアンロックし、以後使い回す。**実装済みだが実機未検証** |
| `navigator.vibrate` | **iOS Safari は Vibration API 未実装。iOS ではバイブは鳴らない。** feature-detect して非対応環境では何もしない(例外も投げない)。Android Chrome 等では有効 |
| バックグラウンドの `setInterval` 抑制 | 表示は差分計算で復帰時に正しく追いつくが、**通知はバックグラウンド中に発火しない**。Issue が「バックグラウンドでの動作保証はスコープ外」としている点と整合 |

音もバイブも効かない場合のフォールバックとして、**超過時に文字色を warn 色に切り替える**
視覚表示を確実に効く手段として実装した。

## 残課題
- **iOS 実機での音の挙動は未検証。** 長時間放置後に `AudioContext` が
  `suspended` に戻る可能性があり、その場合の `resume()` も
  「ユーザー操作起点」の制約で失敗しうる
- `localStorage` が使えない環境では、画面遷移をまたぐ復元だけ効かなくなる
  (機能自体は継続)
- 休憩時間そのものの記録・保存はスコープ外
