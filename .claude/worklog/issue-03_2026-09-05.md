## 設計上の判断

### 1. `Routine::workouts()` を追加した(Issue 本文に無かった)

エージェントが「仕様に無いが自然に導ける」として追加し、自己申告してきた。
**残す判断をした。** `workouts.routine_id` の FK が既にあり、
「このメニューで何回トレーニングしたか」は後で必ず必要になるため。
Issue 本文のリレーション一覧の記載漏れだった。

### 2. enum は DB 側も `enum` 型にした

`string` + アプリ側バリデーションでも成立するが、DB 制約として不正値を弾ける方が安全。
値の追加時にマイグレーションが必要になるトレードオフは受け入れる
(`movement_type` / `muscle_group` / `equipment` はいずれも増えにくい分類軸のため)。

### 3. マイグレーションのタイムスタンプを依存順に固定した

exercises → routines → routine_exercises → workouts → workout_sets。
この順でないと FK 作成時に参照先が存在せず失敗する。
