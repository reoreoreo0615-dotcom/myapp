## 対応内容

### ① 記録画面の説明
- **前回と今日の目標の関係を1行で示す。** 数字だけでは、アプリが漸進的過負荷を
  計算しているという中核コンセプトが伝わらないため
- 重量アップ時のみ「(重量が上がりました)」を明示。レップアップとの違いを出す
- 記録ボタンのラベルを `記録` → **`このセットを記録`** に(何が起きるか動詞で示す)
- 初回のみ使い方ガイドを表示
- 記録直後に「Nセット目を記録しました」とフィードバック

### ② 用語の置き換え

| 変更前 | 変更後 |
| --- | --- |
| ルーティン | メニュー |
| 総ボリューム | 総挙上重量 |
| 連続トレーニング | 連続記録 |
| W / WU(ウォームアップ) | アップ |
| TARGET | 目標 |
| 推定1RM | 初出に「1回だけ挙げられる重さの目安」を補足 |

### ③ 画面間の導線
- ダッシュボードに**状況に応じた「次にやること」**:
  進行中あり → 再開 / メニュー0件 → まずメニューを作る / それ以外 → トレーニングを始める
- 履歴0件 → 「まず記録する」
- トレーニング終了後 → 履歴・ダッシュボードへのリンク
- メニュー作成画面に目的を伝える1行説明

## 設計上の判断

### 初回ガイドは localStorage で管理
サーバー側の変更(列追加・マイグレーション・往復)に見合わないため。
ジムでは同一端末を使い続ける前提なので、端末ローカルの状態で十分。
読み書きは try/catch で保護し、プライベートブラウズ等で失敗しても
機能は壊れず「毎回表示される」だけに留まる。

### 説明を増やしすぎないことを原則にした
このアプリの差別化軸は「ジムでの入力速度」。毎回出る説明文は価値を殺す。
**初回のみ / 空状態のみ / 補足は小さく** を徹底した。
