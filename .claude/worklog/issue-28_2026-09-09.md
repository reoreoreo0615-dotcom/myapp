## 実装内容
インターバルタイマーの通知手段を **JavaScript のクラスと継承**で差し替え可能にした。

### 実用上の動機(練習用の実装ではない)
Issue #20 で判明した問題: **iOS Safari は Vibration API 未実装で、iPhone ではバイブが鳴らない。**
従来は音・バイブ・視覚が1つの関数に混ざっており、環境に応じて差し替えられなかった。
ジムは騒がしく音だけでは気づかず、iPhone ではバイブも使えない。

## クラス階層

```
RestNotifier (基底)
  isSupported() → 既定 false
  notify()      → isSupported() なら doNotify() を try/catch 付きで呼ぶ
  label()       → '通知'
  doNotify()    → 何もしない(サブクラスで実装)

├─ SoundNotifier     … Web Audio API。unlock() でアンロック状態を保持
├─ VibrationNotifier … navigator.vibrate。iOS では isSupported() が false
├─ VisualNotifier    … 画面フラッシュ。ほぼ常に利用可
└─ CompositeNotifier … 上記を束ねる
```

**「非対応なら何もしない」「例外を投げない」という共通ロジックを基底クラスに一度だけ実装し、
サブクラスは feature-detect と実際の通知処理という差分だけを書く。**

## ポリモーフィズムとして成立していることの検証

`CompositeNotifier.doNotify()`:
```js
this.notifiers.filter((n) => n.isSupported()).forEach((n) => n.notify());
```

`instanceof` による分岐は一切ない。テストでは以下を渡しても正しく動くことを検証:
- `RestNotifier` を継承した架空のクラス3種
- **クラスですらない `{ isSupported, notify }` だけのダックタイピングのオブジェクト**

後者が動くことが「型を知らない」ことの実証になっている。

## 追加した機能: 使える通知手段の可視化

`RestNotifierStatus.vue` で「音 ○ / バイブレーション × / 画面フラッシュ ○」を表示。

**現状は非対応時に黙って何もしないため、ユーザーは「鳴らない」ことに気づけない。**
iPhone で「バイブは使えません」と分かれば音量を上げるなどの対処ができる。

このコンポーネントも `{label, supported}` の配列を受け取って描画するだけで、
個々の Notifier の型を知らない。

## 設計上の判断

### 通知手段ごとの ON/OFF 切り替えは付けなかった
1. `VibrationNotifier` は iOS で自動的に `isSupported()` が false になり、切るものがない
2. 音と視覚はどちらも「ジムの騒音」「サイレントモード」への安全網であり、
   片方を切れると「気づけない」という元の問題を再導入する
3. 設定画面と永続化を新設するコストに対し、解決したい問題は「状態を表示する」だけで足りる
4. 必要になれば `RestNotifier` に `enabled` を足して
   `CompositeNotifier` のフィルタ条件に加えるだけで実装できる設計にしてある(YAGNI)

### VisualNotifier のクラス除去は animationend で行う
`setTimeout` だとテストに実タイマーが残るため。
