## ① CSVエクスポート

- `response()->streamDownload()` + `fopen('php://output')` で1行ずつ `fputcsv()`。
  リポジトリは `->cursor()`(LazyCollection)を返すため、**全件を配列に展開しない**
- 冒頭に `"\xEF\xBB\xBF"` を書き込み **UTF-8 BOM 付き**。Excel で日本語が化けない
- **論理削除済みを除外**: `activeWorkoutSetsQuery()` 経由なので
  `workout_sets.deleted_at` と `workouts.deleted_at` の両方が除外される(#23 の資産を継承)
- 自分のデータのみ(`where user_id`)。テストで検証

### Opus による実データ検証
```
先頭3バイト: efbbbf          ← UTF-8 BOM
行数: 201                     ← ヘッダー + 200セット
日付,種目,セット番号,重量,回数,RPE,ウォームアップ,メモ
2026-07-11,ベンチプレス,1,22.50,10,,1,
```

## ② RPE の入力UI

**必須にしていない。** これが最重要の制約。入力必須にすると
「タップ1回で記録」という差別化軸そのものを壊す。

- `rpe` は `nullable`。送らなくても記録できる
- `SetRow` の `rpeOpen` は既定 `false`(折りたたみ)。展開しない限り動線は変わらない
- 6.0〜10.0 を 0.5 刻み。`NumberStepper` を流用。`HalfStepIncrement` ルールで検証
- 「未入力にする」で解除できる

`test_recording_a_set_without_rpe_succeeds` で、`exercise_id`/`weight`/`reps` のみの
リクエストがそのまま成功し `rpe` が null で保存されることを検証。
既存の rpe を送らないテストが**すべて無変更で通過**(回帰なし)。

## 設計上の判断
- **エクスポートの期間指定は `from`/`to` の任意日付範囲。**
  既存の `HistoryPeriod`(3ヶ月/6ヶ月/全期間)ではなく、バックアップ用途には
  任意範囲の方が有用と判断
- 導線はプロフィール画面に配置(仕様に指定がなかった)
- 記録画面の完了済みセットにも `RPE n.n` を小さく表示。
  入力後に確認できないと不便なため
- `UpdateWorkoutSetRequest` にも `rpe` を追加し、記録済みセットの編集からも修正できるようにした
