## 設計上の判断

### グラフはライブラリを使わず自前の SVG
理由:
- 種目ごとの履歴は多くても数十点。パン/ズーム等の対話性も不要
- デザイントークンが CSS 変数なので、SVG 内で `var(--color-accent)` を直接使えば
  **JS の分岐ゼロでライト/ダークに追従**する
- ライブラリ(Chart.js 等)は数十KBのバンドル増と、テーマ連動のアダプタ層が必要になる

結果: History ページ全体で 8.8KB / gzip 3.5KB、**新規依存パッケージなし**。

### 自重種目の指標切り替え(Issue #17)
```
is_bodyweight = false  →  metric '1rm'   ProgressionService::estimateOneRepMax()
is_bodyweight = true   →  metric 'reps'  トップセットのレップ数
```
**`ProgressionService` は変更していない。** 切り替えは組み立て側で行う。
加重ありの自重種目はレップ数を主軸にしつつ、各点に `+Nkg` を併記し、
自己ベストにも「加重」の項目を出す。

### 自己ベストは期間フィルタの影響を受けない
グラフの期間を3ヶ月に絞っても、自己ベストは全期間の記録を示す。
PR は本来「これまでの最高」であるため。テストで明示的に検証。

### 全セット一覧にはウォームアップも含める
「グラフの注意点」に `is_warmup = false` のみと明記されているのはグラフと自己ベストの話。
一覧は実際に行ったことの記録なので、ウォームアップも小さな「W」タグ付きで表示する。

## 残課題

### `estimateOneRepMax` の式が SQL に重複している
`personalBest()` は `MAX()` を SQL 側で実行する必要があるため、Epley 式を
SQL の `CASE` 式として複製している。PHP 側の実装と乖離するリスクがある。

対策として、**SQL の結果と PHP の式の出力を突き合わせるテスト**を追加済み。
乖離が起きたらテストが落ちる。
