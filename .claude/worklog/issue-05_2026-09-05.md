## 設計上の判断

### `phpunit.xml` を変更せず CI 側で `DB_HOST` を上書きした
`phpunit.xml` は `DB_HOST=db`(Docker Compose のサービス名)を持つが、
GitHub Actions のサービスコンテナには `127.0.0.1` でしかアクセスできない。

PHPUnit は `<env>` に `force` 属性が無い場合、**既存の環境変数を優先**して
phpunit.xml の値では上書きしない。この仕様を利用し、CI ジョブの `env` で
`DB_HOST=127.0.0.1` を設定することで、ローカル用の設定を壊さずに解決した。

### マイグレーションの明示ステップを入れていない
Feature テストは全て `RefreshDatabase` を使っており、テスト実行時に自動で走る。
個別に `php artisan migrate` を挟むと二重管理になる。

## CI が検出した実バグ(重要)

初回実行が **9件失敗**した。

```
Vite manifest not found at: app/public/build/manifest.json
Tests: 9 failed, 66 passed
```

`php artisan test` を `npm run build` より**前**に実行していたため、
ビルド成果物が無い状態で Inertia のページを描画して落ちていた。

**ローカルでは過去のビルド成果物が残っているため再現しない。**
CI を入れて初めて検出できた種類のバグで、CI 導入の価値がそのまま出た形。

修正: ステップ順を `pint --test` → `npm run build` → `php artisan test` に変更。
再実行で **CI グリーン**(Pint 81 files PASS、テスト75件全パス)を確認。
