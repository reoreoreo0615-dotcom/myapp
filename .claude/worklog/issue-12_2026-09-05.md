## 実装内容

Opus 主導・Sonnet 委譲の開発体制を `.claude/agents/` に定義した。

境界は**「判断が要るか」**で引いている。スキーマ設計・命名・トレードオフの決定・
Issue 分解・レビューは Opus が持ち、確定した仕様をコードに落とす作業を Sonnet に渡す。

### 定義した3体(すべて `model: sonnet`)

| エージェント | 担当 | 渡す情報 |
| --- | --- | --- |
| `laravel-backend` | マイグレーション / モデル / リレーション / コントローラ / FormRequest / Policy / サービス / シーダー | 確定したスキーマ定義と受入条件 |
| `vue-frontend` | Inertia ページ / Vue コンポーネント / Tailwind | 画面モックと props の型 |
| `test-writer` | Feature テスト / ユニットテスト / ファクトリ | 期待する入出力の表 |

## 変更ファイル

- `.claude/agents/laravel-backend.md` — バックエンド実装担当の定義
- `.claude/agents/vue-frontend.md` — フロントエンド実装担当の定義
- `.claude/agents/test-writer.md` — テスト実装担当の定義
- `.claude/CLAUDE.md` — 開発規約の本体(既存)
- `CLAUDE.md` — 自動読み込みの入口(`@.claude/CLAUDE.md` を import)

## 設計上の判断

### 1. ツールを `Bash, Read, Write, Edit, Glob, Grep` に限定した

**Agent ツールを与えていない。** サブエージェントがさらに別のエージェントを起動できると
制御不能な再帰が起きるため。WebFetch / WebSearch も外した(実装作業に不要で、
外部情報を勝手に取り込まれると仕様がぶれる)。

### 2. 3体すべてに「事故防止」の指示を共通で埋め込んだ

- **「設計判断はあなたの仕事ではない」** — スキーマや命名を勝手に変えさせない
- **「仕様が曖昧なら勝手に解釈せず報告に明記する」** — 黙って推測で埋められると手戻りになる
- **「テストが落ちたら落ちたまま報告する。通ったように装わない」** — 虚偽報告の防止

`test-writer` には加えて **「テストを通すために実装を書き換えるな」** を明記した。
実装のバグをテスト側で隠蔽されるのが最悪のケースであるため。

### 3. アプリ固有の落とし穴を各定義に書き込んだ

汎用的な Laravel の作法ではなく、このアプリで実際に数字が壊れる箇所を明記した。

- backend: `is_warmup = false` で絞る / N+1 を放置しない / 重量は decimal / Phase2 用の列を消さない
- frontend: 375px 基準 / タップ領域 44×44px / タップ1回で1セット / 二重送信防止
- test-writer: ウォームアップ除外 / 境界値 / 認可の異常系 / トップセットの定義

### 4. `CLAUDE.md` はルートに薄い入口を置き、本体を `.claude/` に置いた

Claude Code が自動で読むのはリポジトリルートの `CLAUDE.md` である一方、
生成物は `.claude/` 配下に集約したいという要件があったため、
ルート側を `@.claude/CLAUDE.md` を import するだけの薄いファイルにした。
