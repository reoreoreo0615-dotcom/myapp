## 前提条件

汗だくの手 / 片手操作 / ジムの弱い電波。この3つを前提に設計する。
**1セット記録するまでのタップ数を1回に固定する。**

## 画面仕様

```
+--------------------------------------+
| 胸の日          2026-09-05    42:15  |
+--------------------------------------+
| ベンチプレス                          |
|  前回: 60×8 / 60×8 / 60×7            |
|  ▸ 今日の目標: 62.5kg × 8回           |
|   1  [62.5]kg [ 8]回   ✓ 完了        |
|   2  [62.5]kg [ 8]回   [記録]        |
|   3  [62.5]kg [ —]回   [記録]        |
+--------------------------------------+
```

- [ ] メニューを選んでワークアウトを開始する(メニューなしの飛び込みも可)
- [ ] 種目ごとに**前回の全セット**を表示する
- [ ] 種目ごとに **ProgressionService が算出した今日の目標**を表示する
- [ ] 入力欄に目標値が**最初からプリセットされている**
- [ ] `[記録]` タップでセットを1件保存し、次のセット行を出す
- [ ] ウォームアップセットとして記録するトグル(`is_warmup`)
- [ ] 経過時間タイマー(`started_at` からの差分)
- [ ] セットの編集・削除

## 実装上の必須事項

- **N+1 が必ず出る。バッチ取得メソッドの追加が必須。**

  Issue #8 で実装済みの `WorkoutSetRepository::lastWorkingSetsFor(int $userId, int $exerciseId)` は
  **種目1件につき2クエリ**発行する。記録画面は5〜8種目を同時に表示するため、
  これをループで呼ぶと **10〜16クエリの N+1** になる。

  → `lastWorkingSetsForMany(int $userId, array $exerciseIds): array` を新設し、
  **種目数によらず2クエリ**で全種目分の前回セットをまとめて取得すること。
  戻り値は `[exercise_id => [セット配列]]` の形が扱いやすい。

  実装後にクエリログでクエリ数を確認し、**種目数を変えてもクエリ数が増えないこと**を
  テストで保証する。結果をこのIssueにコメントで残すこと。
- インデックス `(exercise_id, workout_id)` が効いているか `EXPLAIN` で確認する。
- ボタンのタップ領域は最低 44×44px を確保する。
- 二重送信を防ぐ(連打で同じセットが2件入らないこと)。
