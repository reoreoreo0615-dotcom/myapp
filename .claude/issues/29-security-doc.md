**Laravel が自動でやっているセキュリティ対策を、自分で説明できる状態にする。**

## 動機

現状 XSS / CSRF 対策は Laravel と Vue が自動で処理しており、**自分で書いたコードが無い。**
「フレームワークが守ってくれている」ことは知っていても、
**何をどう守っているかを説明できない。**

このIssueの目的は**コードを書くことではなく、調べて検証し、説明できる形に残すこと。**

## 成果物

`.claude/docs/security.md`(Markdown)

**推測で書かないこと。** すべて実際のコード・設定・HTTPレスポンスで裏を取る。

## 調べて文書化する項目

### ① CSRF
- [ ] Laravel のどのミドルウェアが検証しているか(クラス名とファイルパス)
- [ ] トークンがどこで生成され、どうやってフロントに渡っているか
      (`XSRF-TOKEN` クッキー / `@csrf` / Inertia の場合はどうか)
- [ ] **実際に検証する**: トークン無しで POST を投げて **419** が返ることを確認し、
      レスポンスを貼る
- [ ] `VerifyCsrfToken` の除外設定があるか確認する
- [ ] SPA(Inertia)特有の注意点

### ② XSS
- [ ] Blade の `{{ }}` と `{!! !!}` の違い。どちらがエスケープするか
- [ ] **Vue はどうか。** `{{ }}` と `v-html` の違い
- [ ] **このアプリで `v-html` を使っている箇所があるか実際に grep して報告する**
- [ ] **実際に検証する**: 種目名に `<script>alert(1)</script>` を登録し、
      画面でどう表示されるかを確認する(実行されずエスケープされることを確かめる)
- [ ] CSP(Content-Security-Policy)ヘッダを送っているか確認。送っていないなら
      導入すべきかを判断する

### ③ セッション管理
- [ ] セッションドライバは何か(`SESSION_DRIVER`)。どこに保存されるか
- [ ] `SESSION_LIFETIME=120` の意味と、切れたときの挙動
- [ ] ログイン時に**セッションIDが再生成される**か確認する
      (セッション固定攻撃への対策。`Auth::attempt` の内部で何が起きるか)
- [ ] `HttpOnly` / `SameSite` / `Secure` 属性の設定値を確認する
- [ ] `remember me` のトークンがどう保存・検証されるか

### ④ SQLインジェクション
- [ ] Eloquent とクエリビルダがどうやって防いでいるか(プリペアドステートメント)
- [ ] **このアプリで生SQLや `DB::raw()` を使っている箇所を grep し、
      危険な箇所が無いか確認する**
      (`WorkoutSetRepository` に `DB::table()` や window 関数を使った箇所がある)

### ⑤ 認可(このアプリ固有)
- [ ] Policy が何を守っているか。他ユーザーのデータにアクセスできない仕組み
- [ ] **実際に検証する**: 他ユーザーのワークアウトIDを直接URLに入れて 403 になることを確認

## 書き方の要件

- [ ] **「Laravel が守ってくれる」で終わらせない。** どのファイルの何行目で
      何をしているかまで踏み込む
- [ ] 各項目に**実際に試した結果**(コマンドと出力、HTTPステータス)を貼る
- [ ] **防げていない攻撃、対策していない項目も正直に書く**
      (レート制限、ヘッダの設定漏れ、CSPの不在など)
- [ ] 人に説明する資料として読める文章にする

## 受入条件
- [ ] `.claude/docs/security.md` が作成されている
- [ ] ①〜⑤すべてに、**実際に検証した結果**が根拠として載っている
- [ ] `v-html` と `DB::raw()` の使用箇所が実際に grep されて報告されている
- [ ] CSRF トークン無しの POST が 419 になることを実際に確認している
- [ ] XSS のテスト文字列がエスケープされることを実際に確認している
- [ ] 他ユーザーのデータへのアクセスが 403 になることを実際に確認している
- [ ] **対策できていない項目も正直に列挙されている**
- [ ] 既存テストが全て通る(コード変更は最小限のはず)
