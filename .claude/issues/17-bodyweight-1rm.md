自重種目(`is_bodyweight = true`)で推定1RMが常に 0 になり、履歴グラフが無意味になる。

## 症状

```
懸垂  前回 0.0kg × 10  →  推定1RM 0.0
```

`ProgressionService::estimateOneRepMax()` は `weight === 0.0` のとき 0.0 を返す仕様
(Issue #8 で意図的にそう決めた)。自重種目は加重なしなら `weight = 0` なので、
**推定1RM が常に 0 になり、#11 の推移グラフが平坦線になって価値がゼロ**になる。

対象種目: 懸垂 / ディップス / アブローラー / ハンギングレッグレイズ(既定種目で4件)

## 論点

正しい推定1RMを出すには**体重が必要**だが、体重の記録は Phase 2 の機能で未実装。

```
自重種目の実質的な負荷 = 体重 × 種目ごとの係数 + 加重
(懸垂なら体重のほぼ全部、ディップスも同様、腕立てなら約65%)
```

## 対処案

### 案A: 自重種目は 1RM ではなく「総レップ数」で推移を見せる(推奨)
グラフの縦軸を種目タイプで切り替える。自重種目は
「ワーキングセットの合計レップ数」または「トップセットのレップ数」を推移させる。
**体重の記録なしで今すぐ実装でき、かつ自重種目の進歩を正しく表現できる。**

### 案B: 体重記録(Phase 2)を前倒しし、体重込みで 1RM を算出
正確だが、体重の記録機能とその履歴管理が必要になりスコープが膨らむ。

### 案C: 加重分のみで 1RM を出す
加重ベルトを使い始めるまで 0 のままなので、案Aと比べて劣る。

## 受入条件

- [ ] 自重種目の履歴グラフが意味のある推移を示す
- [ ] 通常種目の 1RM 推移は従来どおり
- [ ] グラフの縦軸ラベルが種目タイプに応じて変わる(「推定1RM」/「レップ数」など)
- [ ] `ProgressionService` に手を入れる場合、既存の35件のテストが壊れないこと
- [ ] 自重種目のケースをテストで検証
