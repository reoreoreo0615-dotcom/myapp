セット間の休憩時間を計るインターバルタイマーを記録画面に組み込む。

## なぜ必要か

**筋トレでは休憩時間が重量と同じくらい重要。** 休憩が短すぎると次のセットで
挙がらず、長すぎると刺激が逃げる。にもかかわらず、多くの人はスマホの
標準タイマーを別アプリで開いて計っている。

Overload は既に記録画面で「セットを記録した瞬間」を捕捉しているので、
**記録と同時にタイマーを自動で開始できる。** これは別アプリでは絶対にできない。

## 仕様

### 自動開始
- [ ] `[このセットを記録]` を押した瞬間にタイマーを自動スタートする
- [ ] 手動での開始・停止・リセットもできる

### 休憩時間の目安
種目の性質で推奨が変わる。**種目マスタの情報から既定値を出す。**

| 種目タイプ | 推奨休憩 | 根拠 |
| --- | --- | --- |
| コンパウンド(`target_rep_max <= 10`) | 180秒 | 高重量・多関節は回復に時間が要る |
| アイソレーション(`target_rep_max > 10`) | 90秒 | 単関節・軽負荷は短くてよい |

- [ ] 種目ごとに既定の休憩時間を提示する
- [ ] ユーザーがその場で変更できる(30秒単位の増減)

### 通知
- [ ] 目標時間に達したら知らせる
- [ ] **音とバイブレーションの両方**(ジムはうるさく、音だけでは気づかない)
- [ ] 通知の方式を検討すること。Web Audio API / Vibration API / 通知API。
      **iOS Safari の制約を必ず調査すること**(バックグラウンドでの動作、
      音の自動再生制限)。制約があれば報告し、できる範囲で実装する

### 表示
- [ ] 記録画面の**常に見える位置**(画面下部固定など)に残り時間を出す
- [ ] 目標時間を超えたら経過時間を出し続ける(止めない)
- [ ] 大きく読める数字(ジムで離れた位置から見る)

## やらないこと
- 休憩時間の記録・保存(セットごとの休憩時間をDBに残す)は**スコープ外**。
  必要になったら別Issueで検討する
- バックグラウンドでの動作保証(ブラウザの制約が大きい)

## 設計上の注意
- **タイマーが記録操作を邪魔しないこと。** 差別化軸は「タップ1回で記録」。
  タイマーのために操作が増えてはいけない
- 画面を離れて戻ってきたときに、経過時間が正しく復元されること
  (`setInterval` のカウントではなく**開始時刻からの差分**で計算する)
- デザイン方針(`.claude/issues/16-design-foundation.md`)の禁止事項を厳守

## 受入条件
- [ ] セットを記録すると自動でタイマーが始まる
- [ ] 種目タイプに応じた既定の休憩時間が提示される
- [ ] その場で休憩時間を変更できる
- [ ] 目標時間到達を音・バイブで知らせる(iOS の制約は調査のうえ報告)
- [ ] 画面を離れて戻っても経過時間が正しい
- [ ] 記録操作の手数が増えていないこと
- [ ] 375px で横スクロールしない
- [ ] 既存テストが全て通る
