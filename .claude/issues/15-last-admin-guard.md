Issue #13 で実装した締め出し防止ガードに漏れがある。

## 現状のガード

- ✅ 自分自身は削除できない
- ✅ 最後の管理者からは管理者フラグを剥奪できない

## 漏れているケース

**「最後の管理者を、別の管理者が削除する」経路がガードされていない。**

```
管理者A と 管理者B が存在する
  → A が B を削除(許可される。この時点で管理者はAのみ)
  → A が自分を削除しようとする → 自己削除ガードで防がれる ✅
```

ここまでは防げるが、以下は通ってしまう:

```
管理者A と 管理者B が存在する
  → B が A を削除
  → B が自分の管理者フラグを剥奪しようとする → 最後の管理者ガードで防がれる ✅
```

実際には自己削除ガードと最後の管理者ガードの組み合わせでほぼ塞がっているが、
**「削除によって管理者が0人になる」ことを直接チェックしていない**のは設計として弱い。
ガードの根拠が「2つの別々のルールの副作用」になっており、将来ルールを変えると穴が開く。

## 対処

`AdminUserController@destroy` に **「削除後に管理者が0人にならないこと」** の
明示的なチェックを追加する。自己削除ガードとは独立したルールとして実装すること。

```php
if ($user->is_admin && User::where('is_admin', true)->count() <= 1) {
    // 最後の管理者は削除できない
}
```

## 受入条件

- [ ] 最後の管理者を削除しようとすると失敗する(自分自身かどうかに関わらず)
- [ ] 管理者が2人以上いれば、管理者を削除できる
- [ ] エラーメッセージが画面に表示される(500 にしない)
- [ ] 上記2ケースの Feature テストがある
- [ ] 既存テストが全て通る
