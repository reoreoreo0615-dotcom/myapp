体重・体脂肪率を記録し、筋力の推移とあわせて見られるようにする。

## なぜ必要か

**筋力の数字は体重を抜きにしては解釈できない。**

- 増量期に挙上重量が伸びるのは当然。体重も増えているなら「強くなった」とは限らない
- 減量期に挙上重量が横ばいなら、それは**実質的には進歩**
- 「ベンチプレス 体重の1.2倍」のような**相対筋力**は、絶対重量より意味のある指標

現状は挙上重量しか記録しておらず、この解釈ができない。

## スキーマ

### `body_logs`

| カラム | 型 | 備考 |
| --- | --- | --- |
| id | bigint unsigned PK | |
| user_id | bigint unsigned | FK cascadeOnDelete |
| measured_on | date | 測定日 |
| weight_kg | decimal(5,2) | 体重。999.99kg まで |
| body_fat_percentage | decimal(4,1) nullable | 体脂肪率。省略可 |
| memo | string(255) nullable | |
| timestamps | | |

- unique: `(user_id, measured_on)` … 1日1件。同日に再入力したら上書き
- index: `(user_id, measured_on)`

> **注意:** `user_id` を削除する際は `DeleteUserService` に
> `body_logs` の削除を追加すること。Issue #13 で作った削除順の仕組みに乗せる。

## 筋力との連携(このIssueの本質)

### 相対筋力の表示
- [ ] 種目別履歴に **「体重比」** を追加する
      例: ベンチプレス 推定1RM 80kg / 体重 68kg → **1.18倍**
- [ ] ワークアウト日に最も近い体重記録を使う(同日が無ければ直近の過去)
- [ ] 体重の記録が無い期間は体重比を出さない(0や推測値で埋めない)

### 自重種目の扱い(Issue #17 の再検討)
Issue #17 で「自重種目はレップ数を軸にする」と決めたが、体重が分かれば
`実質的な負荷 = 体重 + 加重` で推定1RMを出せるようになる。

**ただし種目によって体にかかる割合が違う**(懸垂・ディップスはほぼ全体重、
腕立ては約65%)。正確にやるには種目ごとの係数が必要でスコープが膨らむ。

- [ ] **レップ数を主軸に据える方針は維持する**(#17 の決定を覆さない)
- [ ] 体重記録がある場合のみ、補助情報として `体重 + 加重` の推定1RM を併記する
- [ ] 係数は導入しない。既定種目の自重4種(懸垂/ディップス/アブローラー/
      ハンギングレッグレイズ)はいずれもほぼ全体重がかかる種目のため、係数1.0で扱う。
      **この単純化を画面上で明示すること**(「体重の全部がかかる前提の概算」等)
